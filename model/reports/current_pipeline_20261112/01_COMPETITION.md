# SINCON 2026 대회 정보·평가·데이터 사용 규정

작성 기준: 2026-11-12 로컬 파일 확인 시점. 실제 저장된 코드·설정·CSV·JSON을 기준으로 기술한다. 새 학습을 수행한 보고서가 아니며, 완료된 최신 버전은 v5다. v6는 작업 중인 별도 소스로 분리한다.

## 1. 과제의 정확한 정의

2026 SINCON은 인하대학교 SINSA·INCOM·NETers가 함께 진행하는 인천 지하철 승차 수요 예측 대회다. 과거 승차·하차 관측과 예측 시점에 알려진 정보로 **2026년 7~10월 역별·시간대별 승차 인원**을 한 번에 예측한다.

| 항목 | 내용 |
|---|---|
| 학습 관측 | 2025-01-01~2026-06-30 |
| 최종 예측 기준일(origin) | 2026-06-30 |
| 예측 날짜 | 2026-07-01~2026-10-31, 123일 |
| 공간 개체 | 인천 1·2·7호선, station_id 기준 71개 역 |
| 시간 구간 | 시작 시각 6~23, 06:00~24:00의 18개 한 시간 구간 |
| 정답 | boardings: 해당 구간 승차 인원 |
| 제출 규모 | 123 × 71 × 18 = 157,194행 |
| 공식 평가 | RMSLE, 낮을수록 좋음 |
| 방식 | 정해진 123일 전체를 원점 하나에서 예측하는 다개체 장기 예측 |

예측일이 8월이 됐다고 7월 실제 관측을 추가로 받아 갱신하는 방식이 아니다. 예측일 직전 1일·7일의 실측값이 기준일보다 미래라면 입력으로 사용할 수 없다. 현재 파이프라인은 origin 시점의 과거 통계와 미래 달력을 결합해 각 horizon을 직접 예측한다.

역 이름이 같거나 비슷하더라도 ID가 다르면 별도 개체다. 예를 들어 부평구청 두 노선 역은 별도 행을 예측하며, 연결 정보를 피처로 추가할 수 있을 뿐 정답을 합치지 않는다. 미래 하차 인원은 제공되지 않으므로 입력 피처가 될 수 없다. 학습에서 보조 타겟으로 활용하는 것은 이와 구분한다.

## 2. 평가 산식과 학습 손실

정답과 예측이 0 이상일 때,

$$\operatorname{RMSLE}=\sqrt{\frac1N\sum_i(\ln(1+\hat y_i)-\ln(1+y_i))^2}.$$

`log1p`는 0명에도 정의된다. 로그 공간 제곱오차를 최소화하는 것이 공식 지표와 직접 연결된다. 현재 잔차 모델은 `z=log1p(boardings)`, 과거 기준선 `a`, 잔차 `r=z-a`를 사용한다. 트리의 L2/RMSE, 신경망 승차 MSE가 이 목표와 연결된다. 하차 보조 손실, 표본 가중치, 최종 비음수 절삭 때문에 모든 내부 학습 목적이 공식 평가와 완전히 동일한 것은 아니다.

RMSLE는 MAE와 달리 작은 수요의 상대적 오차도 크게 반영한다. 따라서 전체 평균 인원을 맞추는 것만으로 점수가 좋아지지 않는다. `expm1(E[log1p(Y)])`는 일반적으로 산술 평균 `E[Y]`보다 작다. 음의 MBE만 보고 예측 전체에 상수를 더하거나 로그정규 평균 보정을 하는 것은 지표상 이득을 보장하지 않는다.

## 3. Public / Private의 날짜 구성

사용자가 전달한 공식 Overview에 따르면 7·8·9·10월 **매월 날짜를 대략 절반씩** 나눈다. Public 61일, Private 62일이며 어느 날짜인지는 공개하지 않는다.

| 구분 | 날짜 수 | 날짜당 행 수 | 총 행 수 |
|---|---:|---:|---:|
| Public | 61 | 1,278 | 77,958 |
| Private | 62 | 1,278 | 79,236 |
| 전체 | 123 | 1,278 | 157,194 |

한 날짜의 역·시간 구간은 해당 날짜의 평가 구분에 속한다. Public이 7월 단기 예측에만 집중됐다는 근거는 없다. Local CV와 Public은 계절·날짜·학습량이 다르므로 절대값을 직접 같은 기준으로 비교할 수 없다. 최종 순위는 Private 점수와 규정·재현성 확인 후 확정된다.

## 4. 제출 규격과 횟수

```csv
example_id,boardings
J000000,예측값
J000001,예측값
```

위 예시는 열 형식 설명이며 숫자가 아닌 문자열을 실제 제출하라는 뜻이 아니다. 실제 boardings에는 유한한 0 이상의 실수만 넣는다. 소수 제출이 허용되며 반올림은 필요하지 않다.

- 팀당 하루 최대 10회. 초기화는 한국 시간 오전 9시(00:00 UTC).
- 최종 평가에 사용할 제출은 최대 2개 선택.
- 전체 157,194개 ID가 중복·누락 없이 있어야 한다.
- 로컬 구현에서는 test.csv의 ID를 기준으로 제출 순서를 고정한다.
- **로컬 sample_submission.csv는 117,576행뿐이다.** test.csv의 7~9월 ID 접두 구간만 포함하며 10월 39,618행이 빠져 있다. 대회 설명의 완전한 템플릿과 실제 파일이 다르므로 sample의 행 수로 결과를 자르면 안 된다. 원본 파일은 수정하지 않고 test.csv의 전체 ID를 사용한다.

## 6. 데이터와 외부 정보의 시점 경계

| 정보 | 현재 작업의 처리 원칙 |
|---|---|
| 제공된 2025~2026-06 승하차 | 해당 origin 이전 관측만 특징·통계 적합에 사용 |
| 미래 요일·월·주말 | 날짜에서 결정되므로 사용 가능 |
| 공휴일·임시공휴일·선거일 | 공식 발표일 known_since ≤ origin인 경우에만 노출 |
| 사전 발표 행사·학사·경기 일정 | 발표 시점과 재사용 조건을 확인한 정보만 사용 |
| 사전학습 가중치 | 공개 시점·비상업적 사용 가능 등 대회 조건 및 개별 라이선스 확인 필요 |
| 2026-07 이후 실제 지하철 실적 | 어떤 경로로든 조회해 학습·보정·제출에 사용하는 행위 금지 |
| 미래 실제 날씨·관객 수·행사 결과·경기 취소 | 예측 origin 이후 생긴 사실이므로 사용 금지 |
| Public 점수 | 통상적인 모델 선택의 참고. 정답 역추정용 반복 탐색과 구분 |

최종 origin뿐 아니라 **각 CV origin에도 같은 공개 시점 필터**를 적용한다. 예를 들어 최종 예측에는 알려진 일정이라도 2025년 초 학습 사례에서는 아직 발표되지 않았다면 숨겨야 한다. 미래 라벨은 지도학습 정답으로만 쓰며, 해당 사례의 입력·정규화·집계에는 유입하지 않는다.

현재 v5는 외부 사전학습 가중치를 사용하지 않는다. 트리와 PyTorch 네트워크 모두 제공 데이터에서 학습한다. KBO 편성표는 v5 일정 파일의 `kbo: []`로 제외되어 있다. 송도 펜타포트는 시점·출처가 기록된 두 일정만 포함하고 맥주축제는 제외되어 있다. 대학·고교 학사 변수 일부는 실제 학교별 공지 목록이 아닌 달력 기반 **대리 변수(proxy)**다. v6에 대한 추가 승인은 현재 v5 산출물을 소급 변경하지 않는다.

## 8. 실행 자원 규정과 프로젝트 예산

대회 안내에는 **별도 실행 시간 제한이 없다.** 최종 코드는 Kaggle Notebook 또는 Colab에서 실행 가능한 규모여야 한다. 초기 계획의 9~12시간 추론 한도·주간 GPU 30시간은 이 대회의 공식 강제 조건으로 확인된 내용이 아니며 문서에서 대회 규정으로 사용하지 않는다. 계정별 플랫폼 할당량은 별도 운영 조건이다.

사용자가 정한 전체 파이프라인 1회 예산은 2시간(7,200초)이다. v5 기록상 전체 실행은 2,361.96초로 이 범위 안이다. RunPod의 GPU·CPU 사양과 실효 cgroup CPU 할당을 고려한 스케줄링을 사용했다. 이 과거 소요 시간이 다른 GPU·macOS·Colab에서 그대로 재현되는 것은 아니다.
