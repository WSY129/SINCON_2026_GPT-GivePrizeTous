# SINCON ensemble_v4 구현 및 검증 기록

## 범위와 보존

신규 소스는 `src/v4/`, 신규 설정은 `configs/ensemble_v4.json`, 신규 결과는 `outputs/ensemble_v4/`에 분리했다. v1·v2·v3 모델·설정·코드·제출 파일은 수정하지 않는다. 로컬 997개 기존 파일을 실행 전 SHA-256으로 기록했으며, RunPod에도 별도 보호 목록을 생성한다. 실행 뒤 두 환경의 보존 목록을 다시 대조한다.

실행 한도는 피처 생성, Step A, Step B, 최종 재학습 및 재추론을 합쳐 7,200초다. 이 문서는 구현 설명이며, 실행 성공·점수·시간은 `run_status.json`, `ablation_step_a.json`, 최종 `RESULTS.md`의 실제 기록으로 판단한다. 제미나이의 예상 개선 폭이나 소요 시간은 측정값으로 취급하지 않는다.

## 입력 시점과 원본 자료

모든 통계와 신경망 이력은 `date <= origin`으로 먼저 잘라 계산한다. 각 학습 사례는 `origin < label_date <= min(origin + 123일, cutoff)`를 만족한다. 미래 승하차 관측을 변경해도 전체 125개 피처가 불변인 테스트를 수행한다. 미래 하차량은 TabM 보조 학습 타겟으로만 사용한다.

달력·이벤트는 기존 v3의 `as_of=origin` 및 `known_since` 필터를 재사용한다. KBO 원편성·사후 취소·미허가 민간 행사는 추가하지 않았다. 대학 방학 변수는 기존 일반 달력 대리변수이며 대학 공식 학사일정으로 표시하지 않는다.

검증 정답은 공휴일·개통·장애 여부와 무관하게 폴드마다 157,194행 전부 유지한다. 과거 집계 및 학습 후보에서만 신설역 개통 첫 3일 162행과 기존 장애 키 9행을 제외한다. 전체 역·시간의 급증치를 일괄 삭제하지 않는다.

## 기준선과 피처

- 기존 v3의 100개 피처를 보존하면서 기준선·전년 커널·성장·특수일 통계를 추가한다. 새 피처 프레임은 125열이다.
- 전년 중심일 `d−364`의 ±21일 창에 삼각 가중치 `1−abs(offset)/22`를 적용한다. 정제 유효요일별 가중 중앙값·가중 15% 절사평균과 원시 요일군별 로그 평균·표준편차·85분위수를 분리한다. 절사는 누적 가중치의 양끝 15%를 부분 질량까지 정확히 제거한다.
- 과거 최대 365일의 `q90−q50`과 `z > q50+0.8` 빈도로 급등 체제를 표현한다. 요일군은 월요일/화~금/토요일/일·공휴일이다.
- 연간 성장률은 2026-01-11 이후에만 최근 관측창과 364일 전 관측창의 중앙값 차이를 계산한다. 두 창의 유효 표본 수 중 작은 값을 `n`으로 삼아 `n/(n+12)`로 수축한다. 창이 없으면 0과 가용성 피처로 처리하며 2024년 자료를 생성하지 않는다.
- 신설 3역은 최근 112일의 주간 중앙값에 Theil–Sen 기울기를 적용하고 주당 `[-0.04,+0.08]`로 제한한다. 감쇠 계수 0.92의 합은 주간 정수 부분과 마지막 부분 주를 선형 보간한다. 전년 개통 초기 90일은 커널 가중치를 0.25배로 낮춘다.
- 기존 역은 전년 표본 수 `n/(n+3)`로 전년 기저와 기존 최근 기준선을 결합한다. 진폭 0.75 이상이면 전년 원시 로그 평균 65%·절사평균 35%, 나머지는 절사평균을 쓴다.
- 신설역은 추세 기저에 기존 역의 노선×시간×유효요일 계절 변화를 더한다. 전년 기준창이 없으면 계절 변화는 중립값 0이다.
- Fourier 보조 기저는 역×시간×요일 고정효과와 연중 1~3차 sin/cos를 공동 Ridge(alpha=50)로 적합한다. 전년 표본이 없을 때 Fourier와 최근 기준선을 절반씩 결합한다.
- 근로자의 날·설·추석의 과거 실측 변화량은 관측된 사례만 사용한다. 전야제는 해당 기준일에 이미 알려진 다음 날 공휴일만 사용한다.
- 오후 하차 급증 빈도는 과거 같은 역·월의 13~18시 합이 중앙값의 1.8배를 초과하는 경우로 정의하고, 저녁 승차 로그 증분을 과거 요일군별로 집계한다. 미래 당일 하차 관측은 사용하지 않는다.

## 학습 표본과 호환성

원점별 전체 123일 피처를 공유 캐시로 계산한 뒤 각 폴드 cutoff 이전 라벨만 선택한다. Fold 4 원점 간격은 7일, 나머지는 14일이며 cutoff−14일 경계 원점을 포함한다. 시간 지평별 할당량을 균등하게 유지하고 전년 유효 표본이 2개 이상인 사례를 우선 추출한다.

폴드 최대 150만 행, 최종 최대 200만 행이다. Fold 3·4 80%, 최종 85%의 전년 보유 표본 비중을 요청하되, 후보가 부족하면 비복원 추출 가능한 실제 비율을 `feature_audit.json`에 기록한다. 목표 비율을 맞추기 위한 정답 복제나 미래 관측 사용은 하지 않는다.

신경망 스케일러는 결측 대체 전 유한한 원래 관측만으로 중앙값과 IQR을 적합한다. 유효 표본이 10개 미만인 열은 중앙값 0·IQR 1로 두고, 학습 시 상수인 열의 값 채널을 중립화한다. 원래 결측 마스크는 유지한다. 전년 수준 피처의 결측을 행별 기준선으로 대체한 뒤 로버스트 스케일링하고 [-10,10]으로 제한한다.

## 7개 모델군

1. **LightGBM:** CPU 16스레드, 최대 6,000회, patience 250, learning_rate 0.02, leaves 191, min_child_samples 20, cat_smooth 15, cat_l2 10, L1 0.3, L2 3. `station_hour` 복원, `station_eff_dow` 제외.
2. **CatBoost CPU:** CPU 16스레드 고정, 최대 6,000회, patience 250, learning_rate 0.025, depth 8, l2 5, random_strength 0.8. 교차 범주 두 종류 유지. CPU/GPU의 점수 차이 원인이 하드웨어 하나 때문이라고 단정하지 않는다.
3. **XGBoost:** CUDA hist(없으면 CPU), 최대 6,000회, patience 250, learning_rate 0.02, depth 8, min_child_weight 20, L1 0.3, L2 3, max_cat_threshold 64. `station_hour` 복원, 검증 DMatrix 호환 경로 유지.
4. **TabM v4:** 직접 구현한 BatchEnsemble 방식. K=16, hidden 384, 3블록, 주파수 8, dropout 0.2, batch 2048. AdamW lr 0.0015·weight_decay 0.0003, 3에폭 warmup 후 cosine, 최대 35에폭·patience 7. CUDA FP16+GradScaler, CPU/MPS FP32. 헤드별 승차+0.2×하차 손실을 계산한 뒤 평균한다.
5. **일간 총량·시간대 점유율 분해:** 모든 완전한 학습 후보 역·일의 일간 총량을 CatBoost CPU와 LightGBM으로 학습한다. 점유율 모델은 최대 60,000개의 완전한 역·일 블록을 비복원 추출해 학습하며 18개 softmax의 합은 1이다. 평활 타겟 `(y+0.5)/(total+9)`를 되돌릴 때 **`(pred_total+9)*share−0.5`**를 적용한다. 지시서의 `pred_total*share−0.5`는 하루 합계를 9명 줄이는 산술 오류여서 수정했다. 0 절삭이 작동하는 경우에는 일간 합이 미세하게 달라질 수 있다.
6. **저수요 전문 모델:** `anchor_v4<3.3 또는 hour>=21`인 학습 사례에 LGB(min_child_samples 8, leaves 95, L2 1)와 작은 CatBoost(depth 6)를 학습한다. 게이트 밖은 기준선으로 채워 완전한 OOF 벡터를 만든다.
7. **그래프·시계열 신경망:** 56일 승차·하차 로그와 결측 마스크를 실제 노선 인접·환승 그래프로 혼합하고, 8개 주간 패치를 Transformer에 전달한다. 미래 달력·기준선과 결합해 한 역·일의 18시간 잔차를 동시에 예측한다. 최대 120,000개 완전한 역·일 학습 블록, batch 512, hidden 96, 30에폭·patience 7이다. **공식 iTransformer 구현 재현이 아니라 사용자 명세에 맞춘 별도 그래프/시간 Transformer**이며 내부 모델 키만 `st_itransformer`로 유지한다.

## 검증과 앙상블

Step A는 Fold 3·4에서 앞의 직접 예측 4종만 평가한다. 여러 변경을 묶어 비교하는 실험이므로 개별 피처나 CPU 복원의 단독 인과 효과를 입증하지 않는다. Fold 4 개선과 주요 역 SSE를 먼저 저장한다. 개선하지 못하면 자동으로 Step B 진입을 멈춰 원인을 점검한다.

Step B는 4개 폴드와 7개 모델군의 OOF를 생성한다. Fold 3+4에서 전역 로그 공간 비음수 합1 가중치를 구하고, 신설역→고급등→심야/저수요→일반 순서의 상호배타 버킷 가중치를 별도로 적합한다. 버킷 목적함수는 로그 MSE+0.0005×전역 가중치와의 제곱거리다.

Fold 3에서 Fold 4와 겹치는 날짜를 제거한 뒤 가중치를 적합해 Fold 4에서 평가한다. 버킷이 전역보다 나쁘면 전역 가중치를 사용한다. **이 fallback 선택은 Fold 4 정답을 사용하므로 최종 선택 점수는 독립 검증 점수가 아니다.** fallback 전 교차검증 결과를 함께 남긴다. LOFO 또한 원래 모델의 early stopping·피처 선택에 쓴 검증 라벨을 완전히 분리한 중첩 CV는 아니다.

최종 반복 수는 `round(max(best4, 0.25*best3+0.75*best4)*1.12)`이며, 각 모델군 두 시드(2026·2027)의 로그 예측을 평균한다. 단일 모델·앙상블 모두 같은 행과 산식으로 비교한다. Public 점수를 예측하거나 RMSLE 0.13 달성을 보장하지 않는다.

## 실행과 점검

```bash
python -m unittest tests.test_v4_pipeline -v
python -m src.v4.pipeline run
python -m src.v4.pipeline infer
```

실행 시작 시 입력 CSV·설정·소스 SHA-256을 저장하며 기존 fingerprint와 다르면 중단한다. 최종 결과는 테스트 ID 순서로 복원한다. 신규 제출 파일의 157,194행, ID 고유성, 유한값, 비음수, 분포를 확인한다. 예측 평균이나 최소값을 특정 범위에 강제로 맞추지 않는다. 별도 프로세스에서 모델을 재로딩하고 피처를 재계산해 예측 `allclose`와 CSV SHA-256을 대조한다.

## 실행 중 확인한 교정 사항

- 최초 Step A의 Fourier Ridge가 모든 역×시간×유효요일 고정효과를 0으로 수축하면서 계양·귤현의 대체 기준선을 과소추정했다. 절편에 규제를 걸지 않는 `Ridge(fit_intercept=True, alpha=50, solver="lsqr")`로 수정했다. 최초 실험의 소스·피처 캐시·완료 모델·로그는 `attempt_a_initial/`에 보관했고 수정 후 캐시를 전부 재생성했다.
- 원래 7,200초 마감은 유지한다. 수정 재시작으로 예산을 다시 부여하지 않는다.
- RunPod는 논리 CPU 48개를 표시하지만 cgroup `cpu.max=1020000 100000`으로 실효 할당은 약 10.2코어다. 48개 코어가 전부 전용이라는 전제의 소요 시간 추정은 사용하지 않는다.
- 로컬 및 RunPod에서 수정 후 단위 테스트 10개 통과. 일정한 로그 수요의 Fourier 예측값 보존 검사를 포함한다.

## 제출 ID 기준 및 실험 해석

제공된 `sample_submission.csv`는 117,576행으로 현재 테스트의 157,194행과 다르다. 원본 파일은 수정하지 않으며 제출은 `test.csv`의 157,194개 `example_id`와 원래 순서를 기준으로 생성한다. 열은 `example_id,boardings` 두 개다.

Step A는 기준선·피처·규제·CatBoost 장치·TabM 전처리를 묶어 바꾼 실험이다. 개선을 특정 변경 하나, 특히 CPU/GPU 전환 하나의 인과적 효과라고 주장하지 않는다. 모델별 최적 반복 수가 상한보다 낮으면 실제 early stopping 결과를 사용하며 강제로 더 오래 학습시키지 않는다.

## 최종 재로딩 장치 교정

XGBoost 3.4.1의 저장 모델은 CPU에서 실행 가능하지만, CUDA 예측과 최대 로그 차이 0.194883(시드 2026), 0.162350(2027)이 관측되었다. 같은 저장 모델을 CUDA로 복원하면 두 시드 모두 최대 차이 0이었다. `infer-one`에서 CUDA가 있으면 학습 때 사용한 CUDA 장치를 복원하도록 수정했다. 모델 가중치, 학습 피처, OOF, 최종 예측 파일은 변경하지 않았다.

`fingerprint.json`은 실제 학습 당시 소스 해시로 보존한다. 변경 전 pipeline은 `pipeline_before_reload_fix.py`, 수정 전후 해시와 수치 비교는 `reload_fix_audit.json`에 보관한다. 저장 모델의 동일 제출 재현은 CUDA 환경을 기준으로 검사하며, 다른 CPU·라이브러리 버전에서 비트 단위 동일성을 보장하지 않는다. 완전 재학습은 기존 산출물을 보존한 별도 프로젝트 복사본의 비어 있는 `outputs/ensemble_v4`에서 실행한다. 기존 캐시와 변경된 소스의 혼합은 fingerprint 검사로 거부한다.
