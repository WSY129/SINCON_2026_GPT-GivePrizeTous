# SINCON ensemble_v2 실행 결과

요청한 4-fold × 4모델 CV와 4모델 × 2시드 최종 재학습을 수행했다. 이 문서는 저장된 실제 결과 파일에서 생성했다. 모델·검증 구조와 구현 설명은 [IMPLEMENTATION.md](IMPLEMENTATION.md)에 있다.

## 데이터 감사

실제 train 688,176행, test 157,194행, 71역이다. train 날짜에 빠진 날은 없고 관측된 역·시간 행은 중복·결측·음수가 없다. 개통 전 178일은 68역×18시간=1,224행/일, 이후 368일은 71역×18시간=1,278행/일이다. 학습 승차량 평균 331.9843, 왜도 2.9649, 2025년 7~10월 평균 320.3116다. sample_submission은 실제로 117,576행인 오래된 템플릿이므로 전체 test ID를 제출 범위로 사용했다. 원본 CSV는 수정하지 않았다.

## 테스트·보존·환경

`unit_tests.log`에 53개 unittest 통과 기록이 있다. 미래 값 불변성, 부분 horizon cutoff, 공휴일·개통 마스킹, 전년 휴일 대체, 공개시점, 전처리 미지 범주/직렬화, TabM 출력 차원과 헤드별 손실, convex/LOFO를 검증했다. 실제 데이터의 네 모델 짧은 학습·저장·예측 연결 점검은 `attempt_1_partial_before_elasticity_fix/smoke/`에 보관했다. 첫 실험에서 탄력성의 평일 평균 정제 범위를 발견해 바로잡고, 회귀 테스트를 추가한 뒤 모든 CV와 최종 학습을 다시 실행했다. 첫 실험의 미완료 결과는 현재 점수에 섞지 않았다. 추가로 XGBoost 3.4.1의 검증 입력 경로와 실제 추론 경로 차이를 실제 Fold 3 데이터에서 발견했다. 학습·검증·추론의 pandas 범주 목록을 동일하게 고정한 상태에서, 검증에 추가 참조 범주 변환을 하지 않는 raw DMatrix를 사용하도록 수정했다. 검증 RMSE와 실제 추론 RMSE의 일치 회귀 테스트와 실제 데이터 20회 학습 점검을 통과했다. XGBoost 네 폴드와 두 최종 시드는 모두 재학습했고, 다른 모델 18개의 파일은 해시를 확인하여 유지했다. 변경 전 XGBoost 결과와 소스·입력 해시, 재사용 모델 해시와 수정 근거는 `xgboost_validation_fix/`에 보관했다.

보호 대상 세 파일의 SHA-256이 작업 전과 같다(`preservation_verified.json`). 변경된 기존 소스는 `source_before/`에 보관했다. 새 설정은 configs/ensemble_v2.json 하나이며 새 결과는 이 폴더 아래에 저장했다.

실제 하드웨어 탐지: `{'cuda_count': 0, 'mps': True}`. 전체 실행은 트리 CPU 및 TabM MPS FP32 결과다. 제한된 사전 점검에서는 MPS가 안 보였으나 승인된 실행 환경에서는 정상 감지되었다. CUDA FP16 분기의 코드와 재현 노트북을 제공하지만 T4에서 실행한 결과로 표현하지 않는다. GPU CatBoost나 다른 패키지 버전의 결과는 비트 단위로 같지 않을 수 있다.

## 저장 모델 재로딩과 최종 무결성

16개 CV 모델, 8개 최종 모델, 628,776행 OOF의 고유 fold 키, 제출 157,194개 ID와 순서·유한값·비음수를 확인했다. 입력·소스·설정 해시와 기존 보호 파일 해시도 일치한다. 저장 모델을 별도 프로세스에서 다시 불러 병렬 추론했다. 최대 예측 차이는 0명이고 allclose 검사를 통과했다. CSV 바이트 일치 여부는 True다. 상세는 verification/reload_agreement.json에 있다.

재현 노트북의 내장 29개 파일이 현재 코드와 해시로 일치하며 8개 셀의 코드 문법 검사를 통과했다. CUDA T4 실제 실행 검증은 별도로 필요하다. XGBoost 수정 후 재개 실행 시간은 8.82분이다. 이는 기존에 완료한 다른 모델의 학습 시간을 포함하지 않는다. 수정 전 완료 실행 시간과 모델별 학습 시간은 xgboost_validation_fix/old_outputs/bundle_manifest.json 및 각 result.json에 보존되어 있으며, 전체 작업 시간으로 해석하지 않는다.
