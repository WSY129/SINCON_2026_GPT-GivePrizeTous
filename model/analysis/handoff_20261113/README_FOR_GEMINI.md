# handoff_for_gemini — v20e 이후 정밀 분석용 자료 (2026-11-13 12:30 KST)

## 점수 표기와 규칙

**점수 표기**
- **로컬 검증(OOF)**: 이 저장소의 4-fold 검증기(aligned)로 잰 값.
- **Public(사용자 제공)**: 리더보드 화면 값.
- **추정**: 근거는 있지만 검증하지 않은 판단.

**규칙**
- 리더보드 점수는 어떤 계산·선택·보정에도 쓰지 않는다. 공개 점수를 보고 역추정하거나 반복 조정하는 것은 대회 규칙상 금지다.
- 평가 기간(2026-07~10)의 지하철 승하차는 어떤 출처에서도 쓰지 않는다.
- 이 묶음의 평가 기간 자료는 모두 **버스** 정류장 값이다. 지하철 값은 학습 기간(~2026-06-30)뿐이다.

| 파일 | 로컬 검증(OOF) 전체 / 가중 4-Fold / Fold 3+4 / Fold 4 | Public(사용자 제공) |
|---|---|---|
| v19 | 0.16541 / 0.16333 / 0.16017 / 0.15891 | 제출 안 함 |
| v19e | v19와 같음(추가 항목은 검증 불가) | 0.147859 |
| v20e (현재 최선) | v19와 같음(추가 항목은 검증 불가) | 0.146860 |

- v19e와 v20e는 **26칸(8개 역-날짜)만** 다르다. v20e는 v19e의 행사 항목 크기를 버스 실측으로 다시 잡은 것이다.
- Public 차이(−0.0010)는 방향 확인일 뿐이며, 항목별 크기 조정에 쓰면 안 된다.

## 02_bus_raw — 첫째·둘째 요청 (오늘 새로 조회한 버스 원본과 대조표)

### 조회 방식
- 사이트: 교통카드 빅데이터 통합정보시스템(stcis.go.kr) > 노선·정류장 지표 > 정류장별 이용량.
- 내장 브라우저에서 사이트 화면 기능으로 **한 번에 한 건, 10초 이상 간격**으로 조회했다.
- 원본은 `stcis_raw_dump_final.json`(사이트가 보여 준 표 문자열 그대로)이다. 이를 행 단위로 펼친 것이 `stcis_bus_hourly_long.csv`다.
  - 열: 정류장 ARS, 날짜, 시, 승차, 하차, 조회 시각.
  - 하루 48개 숫자 = 04시부터 다음날 03시까지 승차·하차 교대.
- `query_log.csv`: 조회 112건, 자료가 나온 것 91건. 실패 사유가 같이 적혀 있다.
- 실패와 주의
  - **38824**: 사이트에서 정류장을 찾지 못했다.
  - **38801**: 사이트 이름이 "한라웨스턴파크송도"로, 역 출구 정류장이 아니다. 축제 계산에서는 뺐다.
  - **40841 부평구청역**: 7월 기간에 정류장을 찾지 못했다.

## 04_reproducibility — 넷째 요청

`COLAB_DEPENDENCIES.md`에 상세히 있다. 요약은 다음과 같다.
- MANIFEST 1,034개 파일을 오늘 다시 대조해 전부 일치했다.
- 끝단 재실행(v15 → v19 → v20e) 결과 SHA-256이 같다.
- 끝단이 여는 입력 229개를 실행 중에 추적했다(`traced_inputs_*`). 225개는 MANIFEST와 일치하고, 나머지는 시스템 파일과 재현 코드다. 사용자 폴더 참조는 없다.
- 걸림돌
  - GPU 단계 저장 예측에 의존한다(v2·v4·v5·v11).
  - LightGBM은 스레드 수에 민감하다(12 고정).
  - Python 3.12와 numpy 2.x가 필요하다(1.x에서는 pkl을 열 수 없음).
  - 외부 표는 사람이 모은 사본이다. 전체 실행 스크립트는 끝까지 돌려 본 적이 없다.
- 비공개 GitHub 저장소(`taeyang0505/SINCON`)에 코드와 끝단 입력(약 640MB)을 올렸다. 코랩에서 clone 후 `python -m reproduce.verify_from_stored`로 확인할 수 있다.
